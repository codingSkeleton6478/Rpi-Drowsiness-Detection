# RPi Drowsiness Detection

라즈베리파이 카메라로 운전자 얼굴을 보고 졸음을 감지하는 프로젝트입니다. 대학 졸업작품으로 만들었습니다.

눈을 감고 있는 게 감지되면 바로 알람을 울리지 않고, 먼저 AI가 말을 걸어서 잠을 깨워봅니다. 대화 중에도 계속 눈을 감고 있거나 이미 한 번 졸았던 적이 있으면 그때 알람을 울립니다.

- 영상 분석: dlib 68개 랜드마크로 눈·입 상태 계산 (Raspberry Pi 5에서 처리)
- 음성 대화: OpenAI API 사용 (Whisper → GPT-4o → TTS)
- 기록: 졸음 이벤트를 SQLite에 저장하고 30분마다 음성으로 알려줌

## 동작 흐름

```
카메라 (640×480)
  → 얼굴 검출 + 랜드마크 68개 (dlib)
  → 눈(EAR), 입(MAR), 고개 각도 계산
  → 상태 판단: SAFE / DROWSY / SLEEP
        DROWSY → AI가 말 걸기
        SLEEP  → 알람 + 휴식 안내
```

## 졸음은 이렇게 판단합니다

### 1. 시작할 때 평소 눈 크기부터 잰다

사람마다 눈 크기가 달라서, 기준값을 하나로 고정하면 눈이 작은 사람은 평소에도 졸음으로 잡힐 수 있습니다. 그래서 실행하면 먼저 캘리브레이션을 합니다.

정면을 보고 있는 동안 EAR 값을 50개 모은 뒤, 정렬해서 90% 지점의 값을 평소 눈 크기로 잡습니다. 졸음 기준은 그 값의 85%입니다(최소 0.20). 이때 입 너비도 같이 재서(중앙값) 나중에 웃음을 구분하는 데 쓰기 때문에, 캘리브레이션 중에는 웃거나 입을 크게 벌리지 않는 게 좋습니다.

운전하는 동안에도 눈을 뜨고 있는 프레임이 들어오면 평소 눈 크기에 1%씩 반영해서 기준을 조금씩 갱신합니다.

### 2. 눈 감김 (EAR)

EAR(Eye Aspect Ratio)은 눈 주변 랜드마크 6개로 눈의 세로/가로 비율을 구한 값이고, 눈을 감으면 0에 가까워집니다.

```
EAR = (|p2 - p6| + |p3 - p5|) / (2 × |p1 - p4|)
```

양쪽 눈 평균이 기준보다 낮은 상태가 30프레임 이어지면 졸음으로 봅니다. AI와 대화하는 중에는 말하면서 눈을 가늘게 뜨는 경우가 있어서 60프레임으로 늘렸습니다. 30fps 기준으로 각각 1초, 2초 정도인데, 프레임 수로 세는 방식이라 FPS가 낮으면 실제 시간은 더 길어집니다.

처음 걸렸을 때는 `DROWSY`(1차 경고)로, 그 뒤에 또 걸리면 `SLEEP`으로 판단합니다. 경고가 뜨면 화면에 3초 동안 그 상태를 유지합니다.

### 3. 하품, 깜빡임 점수

눈을 오래 감지 않더라도 하품이나 깜빡임이 잦으면 피곤한 거라고 보고 점수를 쌓습니다.

| 이벤트 | 조건 | 점수 |
| --- | --- | ---: |
| 하품 (`Yawn`) | MAR 0.6 초과가 30프레임 지속 | +30 |
| 깜빡임 (`Fast Blink`) | 5프레임 넘게 감았다가 졸음 기준 전에 뜸 | +5 |

최근 3분 동안 쌓인 점수만 합산하고, 80점이 넘으면 눈을 뜨고 있어도 `DROWSY`로 바꿉니다. 3분 안에 하품을 세 번 하면 90점이라 걸리는 식입니다. 점수 기준은 직접 정한 값이라 의학적으로 검증된 기준은 아닙니다.

### 4. 오탐 줄이기

웃거나 말할 때도 눈이 작아지거나 입이 벌어지기 때문에, 그대로 두면 졸음이나 하품으로 잘못 잡힙니다. 그래서 아래 경우는 예외로 처리했습니다.

- 웃음: 입 너비가 평소의 1.3배를 넘으면 웃는 걸로 보고, 그 뒤 3초 동안은 눈 감김과 하품을 세지 않습니다. 웃기 직전 2초 안에 쌓인 깜빡임 점수도 취소합니다.
- 대화 중: AI와 대화하는 동안은 하품·깜빡임 점수를 쌓지 않고, 눈 감김 기준도 2배로 늘립니다.
- 고개 돌림: 좌우로 40도 넘게 돌리면 화면에 `SIDE LOOK`을 띄우고, 그동안은 눈 감김을 세지 않습니다. 각도는 카메라 보정 없이 추정한 값이라 대략적으로만 봐야 합니다.

## 경고 방식: 먼저 말 걸고, 안 되면 알람

`DROWSY`가 뜨면 AI가 "운전자님! 깜빡 조신 것 같은데? 괜찮아?" 하고 먼저 말을 겁니다. 운전자 대답은 이렇게 처리됩니다.

```
마이크 녹음 (WebRTC VAD로 목소리가 들릴 때만)
  → Whisper로 텍스트 변환
  → GPT-4o가 답변 생성
  → TTS(onyx 목소리)로 읽어줌
```

GPT 답변 끝에 태그를 붙이게 해서, 대화 결과가 졸음 판단에도 반영되게 했습니다. 태그는 읽어주기 전에 지웁니다.

| 태그 | 예시 | 처리 |
| --- | --- | --- |
| `[부정]` | "나 안 잤어" | 오탐으로 보고 점수·카운트 초기화 후 캘리브레이션 다시 |
| `[인정]` | "아 좀 졸리네" | 점수 비우고 졸음 카운트 +1, 잠 깨도록 대화 계속 |
| `[종료]` | "됐어, 그만해" | 대화만 끝내고 감지는 계속 |

대화는 한 번에 최대 5턴이고, 두 번 연속으로 대답이 없거나 인식이 안 되면 끝냅니다.

알람은 두 경우에 울립니다.

- 대화 없이 모니터링하다가 `SLEEP`이 뜬 경우
- 대화 중에 `SLEEP`이 뜬 경우. 처음 조는 거라면 1초 지켜보고, 이미 졸음 카운트가 있으면 바로 울립니다.

알람은 `sounds/alarm.wav`를 최대 3초 재생한 다음 "위험합니다! 당장 휴식을 취하세요!"라고 안내합니다. 대화와 알람은 별도 스레드에서 돌려서 그동안에도 영상 처리는 계속됩니다.

## 기록과 30분 리포트

졸음 카운트가 올라갈 때마다 `driving_log.db`(SQLite)에 한 줄씩 남깁니다. 그리고 30분마다 최근 30분 기록을 확인해서, 한 번이라도 있으면 "지난 30분 동안 졸음이 N번 감지되었습니다"라고 음성으로 알려줍니다. 그 시점에 대화나 알람이 진행 중이면 그 회차는 건너뜁니다.

카메라 영상은 저장하거나 외부로 보내지 않습니다. 음성은 `user_input.wav`로 저장된 뒤 Whisper API로 전송되고, TTS 결과는 `ai_response.mp3`로 저장됩니다.

## 만들면서 바꾼 것들

- dlib 얼굴 박스가 너무 타이트해서 눈·입 랜드마크가 경계에 걸리길래 박스를 위아래로 10%씩 늘렸습니다. 처음엔 좌우도 10% 늘렸는데 배경이 같이 잡히면서 입이 실제보다 크게 인식돼서 좌우는 뺐고, 아래쪽도 20%였던 걸 10%로 줄여서 위아래 균형을 맞췄습니다.
- 눈 감김 기준은 처음에 60프레임(약 2초)이었는데 30프레임(약 1초)으로 줄였습니다.
- 하품 기준 MAR은 0.5로 하니까 그냥 입을 벌린 것도 하품으로 잡혀서 0.6으로 올렸습니다.
- `SLEEP`일 때 점수를 60점 더 주는 것도 넣었었는데, 누적 점수 계산이 꼬여서 뺐습니다.
- 어두운 환경을 생각해서 감마 보정을 넣어봤는데, 노이즈가 심해져서 오히려 인식이 더 안 됐습니다. 함수는 `utils.py`에 남겨뒀지만 쓰지 않고, 야간은 적외선 카메라로 해결하는 게 맞다고 봤습니다.
- 녹음은 처음에 정해진 시간 동안 했는데, 침묵까지 녹음되니까 API 비용도 나가고 인식도 잘 안 됐습니다. 그래서 VAD를 붙여서 목소리가 들릴 때 녹음을 시작하고, 1초 조용하면 끊도록 바꿨습니다.
- 조용한 구간이 Whisper에 들어가면 "시청해 주셔서 감사합니다", "구독" 같은 유튜브 자막 문구가 튀어나와서, 이런 문구가 들어간 결과는 버리게 했습니다.
- 대화하면서 고개를 끄덕이거나 눈을 길게 감을 수도 있어서, 처음 조는 상황이면 대화 중에 `SLEEP`이 떠도 1초는 지켜보고 알람을 울립니다.

## 프로젝트 구조

```
Rpi-Drowsiness-Detection/
├── main.py          # 메인 루프, 대화/알람 우선순위, DB 기록
├── src/
│   ├── detector.py  # 얼굴 검출, 랜드마크 추출
│   ├── analyzer.py  # 캘리브레이션, EAR/MAR, 고개 각도, 피로도 점수
│   ├── chatbot.py   # VAD 녹음, STT, GPT, TTS, 알람
│   ├── database.py  # SQLite 기록/조회
│   └── utils.py     # EAR, 입 너비 계산 (감마 보정은 미사용)
├── sounds/
│   └── alarm.wav
├── models/          # 직접 받아야 함 (아래 참고)
└── .env             # 직접 만들어야 함
```


## 실행해보기

### 준비물

- Raspberry Pi 5 + Camera Module 3 Wide
- 마이크, 스피커 (시스템 기본 장치로 잡힌 걸 사용)
- 모니터 (결과 화면을 `cv2.imshow`로 띄워서 GUI 환경이 필요)
- 인터넷 연결, OpenAI API 키

### 설치

```bash
git clone https://github.com/codingSkeleton6478/Rpi-Drowsiness-Detection.git
cd Rpi-Drowsiness-Detection

sudo apt update
sudo apt install -y \
  python3-picamera2 python3-opencv python3-numpy \
  python3-venv python3-dev python3-pip \
  build-essential cmake pkg-config \
  portaudio19-dev libasound2-dev \
  wget bzip2 alsa-utils

# Picamera2는 apt로 설치한 걸 써야 해서 --system-site-packages로 가상환경을 만듭니다
python3 -m venv --system-site-packages .venv
source .venv/bin/activate
pip install dlib openai python-dotenv pygame PyAudio webrtcvad
```

dlib은 pip로 설치하면 소스 빌드라 시간이 꽤 걸립니다. 메모리가 부족하면 빌드가 실패할 수 있어서, 그럴 땐 swap을 늘려보세요.

### 랜드마크 모델 받기

용량이 커서 저장소에는 안 올렸습니다.

```bash
mkdir -p models
wget https://dlib.net/files/shape_predictor_68_face_landmarks.dat.bz2 -P models
bzip2 -d models/shape_predictor_68_face_landmarks.dat.bz2
```

`models/shape_predictor_68_face_landmarks.dat`이 있으면 됩니다.

### API 키

프로젝트 폴더에 `.env` 파일을 만들고 키를 넣습니다.

```
OPENAI_API_KEY=여기에_본인_키
```

키가 없으면 시작하자마자 챗봇 초기화에서 에러가 납니다. 카메라 감지만 따로 돌리는 모드는 아직 없습니다.

### 실행

```bash
python main.py
```

모델, 사운드, DB 경로가 상대경로라서 꼭 프로젝트 폴더에서 실행해야 합니다.

1. 실행하면 `CALIBRATING` 화면이 뜹니다. 정면을 보고 평소처럼 눈을 뜨고 있으면 50개가 모이는 대로 끝납니다.
2. 그 다음부터 감지가 시작되고, 화면 아래에 피로도 점수(`Score`), 졸음 카운트(`Count`), 대화 중 여부(`Speak`)가 나옵니다.
3. `q`를 누르면 종료, `r`을 누르면 캘리브레이션을 다시 합니다.

카메라나 마이크가 안 잡히면 `rpicam-hello --list-cameras`, `arecord -l`로 먼저 확인해보세요.

## 주요 설정값

`src/analyzer.py` 위쪽에 모아뒀습니다.

| 이름 | 값 | 설명 |
| --- | ---: | --- |
| `EAR_CONSEC_FRAMES` | 30 | 눈 감김 판정 프레임 (대화 중엔 2배) |
| `MAR_THRESHOLD` | 0.6 | 하품 기준 |
| `MAR_CONSEC_FRAMES` | 30 | 하품 판정 프레임 |
| `YAW_THRESHOLD` | 40 | 고개 돌림 각도 |
| `CALIBRATION_FRAMES` | 50 | 캘리브레이션 샘플 수 |
| `SMILE_RATIO` | 1.3 | 평소 입 너비 대비 웃음 기준 |
| `SMILE_COOLDOWN` | 3초 | 웃은 뒤 판정을 쉬는 시간 |
| `CRITICAL_HOLD_TIME` | 3초 | 경고 상태 유지 시간 |
| `SCORE_WINDOW` | 180초 | 피로도 점수 합산 구간 |
| `FATIGUE_THRESHOLD` | 80 | 피로도 경고 기준 |

사용하는 모델(`whisper-1`, `gpt-4o`, `tts-1`)과 녹음 설정은 `src/chatbot.py`에 있습니다.

## 한계와 개선 방향

- 눈 감김을 프레임 수로 세고 있어서 FPS에 따라 판정 시간이 달라집니다. 경과 시간 기준으로 바꾸는 게 다음 목표입니다.
- 경고가 뜨면 3초 동안 화면 표시를 유지하는데, 그동안은 판정도 같이 멈춥니다. 화면 표시와 실제 판정을 분리하려고 합니다.
- 얼굴이 안 보이거나(`NO_FACE`) 고개를 오래 돌리고 있을 때(`SIDE LOOK`)는 아직 경고하지 않습니다. 운전자를 못 보고 있는 상황도 위험 상황으로 다뤄야 한다고 생각합니다.
- 대화와 알람 뒤 음성 안내는 OpenAI API를 쓰기 때문에 인터넷이 끊기면 동작하지 않습니다. 알람음은 로컬 파일이라 울리지만, 경고 기능은 네트워크 없이도 온전히 동작하도록 분리하는 게 맞다고 봅니다.
- 야간에는 일반 카메라로는 한계가 있어서(감마 보정도 효과가 없었음) 적외선 카메라를 써보고 싶습니다.
- 정확도나 경고까지 걸리는 시간은 아직 측정하지 못했습니다. 녹화 영상을 넣어서 반복 테스트할 수 있는 모드를 만들어 측정해보려고 합니다.
